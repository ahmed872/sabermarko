# إصدار نسخة جديدة — SaberMarko POS

## ما الذي يحدث تلقائيًا
عند دفع tag بالشكل `vX.Y.Z` (مطابق لـ `version` في `package.json`) يعمل `.github/workflows/release.yml` على جهاز
Windows حقيقي من GitHub ويقوم بالآتي:

1. **بوابة الإصدار** (`tools/release/check-release.mjs`): رقم الإصدار = الـtag، يوجد قسم له في `CHANGELOG.md`،
   البرنامج **لا يحتوي مفتاح الترخيص التجريبي (dev)**، ولا توجد أي مفاتيح أو كلمات سر في المستودع.
2. فحص الأنواع + اختبارات الوحدات على Windows.
3. بناء المُثبّت `SaberMarko-POS-Setup-X.Y.Z.exe` (NSIS، **غير موقّع**).
4. حساب `SHA256SUMS.txt`.
5. اختبار تثبيت صامت ثم إزالة صامتة للتأكد أن المُثبّت يعمل (هذا ليس اختبارًا لتشغيل واجهة البرنامج).
6. نشر GitHub Release بالملفين وملاحظات الإصدار (`docs/release-notes/vX.Y.Z.md` أو قسم CHANGELOG).

لا يستخدم أي من الـworkflows أي secret غير `GITHUB_TOKEN` الافتراضي، ولا يرفع أي مفتاح خاص أو كلمة سر أو شهادة.
التشغيل اليدوي (Run workflow) يبني المُثبّت كـartifact للتجربة فقط بدون نشر.

## الخطوات (مرة واحدة قبل أول إصدار تجاري)
1. على **جهازك أنت** (وليس على GitHub أو أي خادم):
   ```bash
   npm run license:keygen                 # المفتاح الخاص يُحفظ في ~/.sabermarko-vendor-keys/ خارج المستودع
   # أو بتشفير إضافي بكلمة مرور:
   read -s PASS && SBM_KEY_PASSPHRASE="$PASS" npm run license:keygen   # تكتب كلمة المرور ولا تظهر ولا تُحفظ
   ```
   الأداة **ترفض** حفظ المفتاح الخاص داخل أي مستودع git، وتكتب المفتاح العام فقط في
   `src/main/license/public-key.ts` وتطبع بصمته (fingerprint).
2. احتفظ بنسختين من المفتاح الخاص offline (فلاشة مشفّرة + مكان آخر). من يملكه يستطيع إصدار تراخيص.
3. `git add src/main/license/public-key.ts && git commit` — هذا الملف آمن (مفتاح عام).
   خطاف `pre-commit` (يُفعَّل تلقائيًا مع `npm install`) يمنع أي commit يحتوي مفتاحًا خاصًا أو ملف ‎.pem/.pfx أو كلمة سر.

## كل إصدار
```bash
# 1) حدّث الرقم والتغييرات
npm version 1.0.1 --no-git-tag-version
#    أضف "## [1.0.1]" في CHANGELOG.md (واختياريًا docs/release-notes/v1.0.1.md)
# 2) تحقق محليًا
npm run release:check -- v1.0.1 && npm test
# 3) ادفع ثم أنشئ الـtag
git commit -am "Release 1.0.1" && git push
git tag v1.0.1 && git push origin v1.0.1
```

## إصدار ترخيص لعميل
```bash
npm run license:issue -- --machine 9F2C1-0B7A4-33D10-AA0F2 --customer "سوبر ماركت البركة" --type permanent --edition standard
npm run license:issue -- --machine 9F2C1-... --customer "..." --type temporary --days 365 --max-users 8
npm run license:verify -- SBM1.xxxx.yyyy --machine 9F2C1-0B7A4-33D10-AA0F2
```
`license:issue` يتحقق من أن المفتاح الجديد يعمل مع المفتاح العام المبني في البرنامج قبل طباعته.
الباقات: `basic` = 2 مستخدمين نشطين، `standard` = 5، `professional` = 15، و`--max-users` يتجاوز الباقة.
مفاتيح بدون باقة (مثل مفاتيح الإصدارات الأقدم) تعمل كما هي بحد 10 مستخدمين.

## التوقيع الرقمي — بأمانة
- المُثبّت **غير موقّع** لأنه لا توجد شهادة Code Signing. GitHub Releases **لا** يوقّع الملفات.
- النتيجة: قد يظهر تحذير Windows SmartScreen. البصمة SHA256 المنشورة تثبت أن الملف لم يتغير، لكنها لا تُغني عن التوقيع.
- عند الحصول على شهادة: أضف `CSC_LINK` و`CSC_KEY_PASSWORD` كـ **GitHub Secrets** (وليس في الملفات)، وغيّر
  `CSC_IDENTITY_AUTO_DISCOVERY` في release.yml.

## ما تم التحقق منه وما لم يتم
| البند | الحالة |
|---|---|
| بناء مُثبّت Windows (NSIS x64) على Windows runner | آلي في release.yml |
| الحجم، رقم الإصدار داخل الـexe، الملفات، الاختصارات | آلي في release.yml |
| تشغيل البرنامج المُثبّت على Windows: العملية تعمل + إنشاء قاعدة البيانات + سجل «app started (win32)» | آلي في release.yml |
| إزالة صامتة مع بقاء بيانات المحل | آلي في release.yml |
| الواجهة على شاشة حقيقية، الطباعة على طابعة حرارية، قارئ الباركود USB | **يدوي — القائمة التالية** |

## الحصول على ملف التثبيت للتجربة (بدون نشر رسمي)
GitHub ← Actions ← **Release** ← Run workflow (على الفرع) ← بعد النجاح افتح التشغيل ← أسفل الصفحة **Artifacts** ← `windows-installer`.
الملف المضغوط يحتوي `SaberMarko-POS-Setup-<الإصدار>.exe` و`SHA256SUMS.txt` (متاح 30 يومًا). هذا البناء يستخدم مفتاح الترخيص التجريبي —
للتجربة فقط، وبوابة الإصدار تمنع نشره رسميًا.

## قائمة اختبار Windows 10/11 الحقيقي (علّم ✓ أمام كل بند)
> قبل البدء: `Get-FileHash .\SaberMarko-POS-Setup-<الإصدار>.exe` يطابق `SHA256SUMS.txt`. سيظهر تحذير SmartScreen لأن الملف غير موقّع:
> **More info ← Run anyway**.

### 1. التثبيت والتشغيل
- [ ] التثبيت يكتمل، ويظهر اختصار «سابر ماركو» على سطح المكتب وفي قائمة ابدأ.
- [ ] البرنامج يفتح بالعربية من اليمين لليسار، والخطوط واضحة.
- [ ] شاشة الإعداد الأول: اسم المحل، الهاتف، الشعار، العملة، نوع الطابعة، حساب المالك.
- [ ] شريط «نسخة تجريبية — متبقٍ 20 يوم» ظاهر.

### 2. نقطة البيع
- [ ] إضافة منتج بالقطعة بسعر وباركود؛ إضافة منتج **بالوزن** (كيلو)؛ منتج له **كرتونة** = 12 قطعة.
- [ ] البيع بالباركود من القارئ USB: مسح نفس المنتج 5 مرات بسرعة ← الكمية 5 (لا تضيع قراءة).
- [ ] بيع بالوزن (مثلًا 0.750 كجم) والسعر صحيح؛ بيع كرتونة كاملة ← المخزون ينقص 12 قطعة.
- [ ] الدفع نقدًا مع باقي، بطاقة، آجل لعميل (يحتاج موافقة المدير للكاشير).
- [ ] الإيصال: يُطبع ويظهر اسم المحل والأصناف والإجمالي والباقي بشكل صحيح.

### 3. المخزون والدفعات والصلاحية
- [ ] الإعدادات ← تفعيل «تواريخ الصلاحية والدفعات».
- [ ] منتج بصلاحية (مثل لبن): شراء **10 كراتين** × 12 بتكلفة 200 وصلاحية بعد 20 يومًا ← المخزون 120 قطعة في دفعة واحدة.
- [ ] شراء **دفعة ثانية** لنفس المنتج بتكلفة 220 وصلاحية أبعد ← دفعتان منفصلتان في شاشة المخزون ← الصلاحية.
- [ ] بيع 130 قطعة ← تُستهلك الدفعة الأقرب انتهاءً أولًا (FEFO).
- [ ] شاشة الصلاحية: المستوى (قريب/قريب جدًا)، المورد، التكلفة، القيمة، الأيام المتبقية.
- [ ] الرئيسية تعرض تنبيه «⚠️ يوجد … ستنتهي خلال … يومًا».
- [ ] «إرجاع للمورد» لجزء من الدفعة ← الكمية تنقص من هذه الدفعة فقط، ورصيد المورد ينقص بقيمة المرتجع، ويظهر في المشتريات ← مرتجعات الشراء.
- [ ] محاولة إرجاع أكثر من كمية الدفعة ← رسالة رفض.
- [ ] **منتج منتهي:** غيّر تاريخ الجهاز مؤقتًا أو اشترِ بتاريخ صلاحية أمس ← محاولة بيعه ← رسالة «لا يمكن بيع … منتهية الصلاحية» ولا تتم الفاتورة. (أرجع تاريخ الجهاز بعدها.)

### 4. المستخدمون والصلاحيات
- [ ] إضافة مدير وكاشير؛ الكاشير لا يرى التكلفة والأرباح والإعدادات.
- [ ] خصم كبير من الكاشير يطلب موافقة المدير.
- [ ] حد المستخدمين: «المستخدمون النشطون: X من Y»، وإيقاف مستخدم يحرر مكانًا.
- [ ] تغيير كلمة المرور من زر القفل.

### 5. النسخ الاحتياطي والاستعادة
- [ ] «إنشاء نسخة الآن» ← «الحالة: سليمة وتم التحقق منها».
- [ ] «حفظ نسخة على فلاشة» ← الملف على الفلاشة.
- [ ] استعادة نسخة أقدم ← البيانات ترجع لحالتها، ونسخة «قبل استعادة» موجودة.
- [ ] **جهاز نظيف آخر:** تثبيت ← «عندي نسخة احتياطية» ← اختيار الملف من الفلاشة ← الدخول بكلمة مرور المالك القديمة.

### 6. الترخيص
- [ ] الفترة التجريبية تعمل والعداد صحيح.
- [ ] بعد توليد مفتاحك الإنتاجي: `npm run license:issue -- --machine <كود الجهاز> ...` ← لصق الكود ← «مفعّل».

### 7. الطابعات
- [ ] حرارية 80 مم: عرض الإيصال، اللغة العربية، القص.
- [ ] حرارية 58 مم (إن توفرت).
- [ ] A4 (إن توفرت): فاتورة كاملة.

### 8. الاسترداد بعد المشاكل
- [ ] إغلاق البرنامج وإعادة فتحه ← البيانات موجودة.
- [ ] تسجيل خروج ودخول بمستخدم آخر.
- [ ] إنهاء البرنامج من Task Manager أثناء العمل ← يفتح مرة أخرى والبيانات سليمة.
- [ ] تحديث: تثبيت إصدار أحدث فوق الحالي ← البيانات باقية.
- [ ] إزالة البرنامج ← بيانات `%APPDATA%\SaberMarko POS` باقية؛ إعادة التثبيت ← كل شيء يعود.

أرسل نتيجة هذه القائمة (وصور أي مشكلة) — آخر بندين في بوابة الإصدار («تشغيل حقيقي على Windows» و«طابعة حرارية حقيقية») لا يكتملان إلا بها.
