## 2. المطابقة المالية والمخزنية (مدقق مستقل لا يستورد أي كود من البرنامج)
- رصيد كل صنف في كل مكان = مجموع حركاته = نموذج الظل المستقل: **1,769/1,769**.
- سلسلة دفتر الحركة متصلة (قبل/بعد) في **152,260** حركة؛ لا رصيد سالب؛ الدفعات = الرصيد في كل الأصناف ذات الصلاحية.
- الافتتاحي + الوارد − المنصرف = الختامي = لقطة ليلة آخر الشهر — **12 شهرًا، 0 اختلاف على مستوى الصنف**.
- كل فاتورة (55,791) وكل سطر (131,461) يجمع صحيحًا: الخصومات، المدفوع، الآجل، الباقي، تكلفة البضاعة.
- الأرباح الشهرية المعاد حسابها من البيانات الخام = ما يعرضه البرنامج **12/12**، وتكلفة البضاعة = دفتر المخزون.
- أرصدة 160 عميلًا و18 موردًا: الرصيد المخزّن = دفتر الحساب = المستندات = نموذج الظل.
- 834 وردية: المتوقع = الافتتاحي + الحركات، والعجز/الزيادة المسجلة = ما تم زرعه عمدًا بالضبط.
- 365 إغلاق يوم ما زالت مطابقة للبيانات، ولم تُضف أي فاتورة ليوم بعد إغلاقه.
- **اختبار أن المدقق نفسه يعمل:** تعديل 3 قيم يدويًا في نسخة ← اكتشف 6 فحوصات فاشلة.
- نتيجة السنة (بيانات وهمية): صافي مبيعات 14.52 مليون ج.م، مجمل ربح 12.7%، صافي ربح 1.33 مليون ج.م.
  لاحظ المدقق تآكل الهامش من 14.2% إلى 10.6% خلال السنة بسبب زيادات الموردين — وهو ما يجب أن يراه المالك في التقارير، وقد ظهر.

## 3. النسخ الاحتياطي والاستعادة
| البند | القيمة |
|---|---|

| مطابقة بعد الاستعادة | جدول بجدول = النسخة، ونسخة الشهر 12 = المحل الأصلي تمامًا؛ والمدقق الكامل 40/40 على القاعدة المستعادة |
| نسبة نجاح الاستعادة | **7/7** |
| الملفات التالفة | **6/6 مرفوضة**: بايت تالف، ملف مقطوع، ملف عشوائي، ملف فارغ، نسخة برنامج آخر، نسخة إصدار أحدث — البيانات الحالية لم تُمس والبرنامج يعمل بعدها |

**سياسة الإصدارات:** نسخة من إصدار أقدم ← تُستعاد وتُرقّى تلقائيًا (تم اختبار v1 ← v2). نسخة من إصدار **أحدث** ← تُرفض برسالة
«هذه النسخة الاحتياطية من إصدار أحدث من البرنامج. حدّث البرنامج أولًا.»

**مسار الاستعادة للمستخدم:** اختيار الملف ← فحص ← عرض اسم المحل والتاريخ والمحتوى ← تحذير ← تأكيد صريح ← نسخة أمان «قبل استعادة»
في مجلد النسخ ← استعادة ← فحص سلامة وعدّ ← إعادة تحميل آمنة. متاح من أول شاشة (جهاز جديد)، ومن شاشة الإصلاح، ومن صفحة النسخ.
صفحة النسخ: آخر نسخة/الحالة ✓ سليمة/الحجم + الأزرار الأربعة، وتنبيه «⚠️ لم يتم إنشاء نسخة احتياطية منذ X أيام» بعد 7 أيام.

## 4. المستخدمون والترخيص
- الحد الأقصى للمستخدمين **النشطين** يأتي من الترخيص وليس من الكود: أساسية 2، قياسية 5، احترافية 15، أو `--max-users`؛
  المفاتيح القديمة بدون باقة تعمل كما هي بحد 10 (تم اختبار التوافق).
- اختُبر: الإضافة حتى الحد ← رفض التالي برسالة عربية ← الإيقاف (بدون حذف، يبقى السجل) يحرر مكانًا ← إعادة تفعيل موقوف عند الامتلاء مرفوضة.
  وفي المحاكاة: محاولة تجاوز الحد رُفضت عند 10 مستخدمين نشطين.
- كلمات المرور مُشفّرة (hash) + شاشة تغيير كلمة المرور لكل مستخدم.
- **فحص صلاحيات شامل لكل مسارات البرنامج كـ«كاشير»:** كل ما خارج المسموح = FORBIDDEN، ولا يظهر أي رقم تكلفة أو ربح.
  هذا الفحص اكتشف تسريب سعر التكلفة للكاشير في دفتر الحركة والدفعات والصلاحية — **تم إصلاحه**.
- حدود الترخيص (الباقة، الحد، الخصائص) داخل التوقيع: تعديلها في المفتاح يُبطله (مُختبر).

## 5. المفتاح الخاص للترخيص
- **لم يتم إنشاء أو رفع المفتاح الخاص النهائي.** المفتاح الحالي في البرنامج مفتاح تطوير، وبصمته مسجلة في قائمة مرفوضة لبوابة الإصدار.
- `npm run license:keygen` على جهازك: يحفظ المفتاح الخاص في `~/.sabermarko-vendor-keys/` و**يرفض** أي مجلد داخل مستودع git، مع تشفير
  اختياري بكلمة مرور، ويكتب المفتاح العام فقط في البرنامج ويطبع بصمته.
- `license:issue` يتحقق قبل الطباعة أن المفتاح الجديد يعمل مع البرنامج؛ `license:verify` لفحص أي مفتاح.
- خطاف `pre-commit` + فحص في CI يمنعان أي مفتاح خاص أو شهادة أو `.env` أو كلمة مرور من دخول المستودع —
  **تم اختباره فعليًا: رفض commit يحتوي مفتاحًا خاصًا، ورفض حتى مثالًا في التوثيق.** تاريخ git كاملًا لا يحتوي أي مفتاح خاص.

## 6. GitHub Releases و Windows
- `.github/workflows/ci.yml`: Linux (فحص أسرار، أنواع، 81 اختبار وحدات، بناء، 9 اختبارات E2E، محاكاة قصيرة + مدقق) و Windows (أنواع + 81 اختبار). **آخر تشغيل: ناجح بالكامل.**
- `.github/workflows/release.yml` عند tag `vX.Y.Z`: بوابة الإصدار ← اختبارات على Windows ← بناء NSIS ← SHA256 ← حالة التوقيع ← تثبيت/إزالة صامتة ← نشر Release.
  لا يستخدم أي secret ولا يرفع أي مفتاح. تم تشغيله يدويًا (بناء فقط، بدون نشر) **3 مرات على جهاز Windows حقيقي من GitHub — ناجح**.
- آخر بناء Windows (commit `5c2fafa`): `SaberMarko-POS-Setup-1.0.0.exe` — 115 MB —
  SHA256 `b7fa738e78772162bf72c09d000ab138fc50421e6b9a46128bd7b8646a45d8a4` — Authenticode: **NotSigned**.
  (البصمة تتغير مع كل بناء؛ البصمة الرسمية هي المنشورة مع الإصدار في `SHA256SUMS.txt`.)
- **لم يتم نشر أي Release** ولم يُدفع أي tag — هذا قرارك بعد توليد مفتاحك.
- **Windows installer build verified. Runtime verification requires a real Windows 10/11 machine.**
  GitHub Release لا يجعل المُثبّت موقّعًا؛ سيظهر تحذير SmartScreen حتى تحصل على شهادة توقيع كود.

## 7. ما اكتشفته هذه المرحلة وتم إصلاحه (أخطاء حقيقية، ليست إضافات)
1. **ضياع قراءة باركود متكررة:** مسح نفس المنتج مرتين بسرعة كان يُسقط القطعة الثانية من الفاتورة (اكتشفه CI على جهاز أسرع). أصبح المسح في طابور بالترتيب، مع اختبار يكتب 7 قراءات بلا تأخير — يفشل على الكود القديم وينجح الآن.
2. **تسريب سعر التكلفة للكاشير** في دفتر الحركة والدفعات وقائمة الصلاحية.
3. **اقتراح خصم على بضاعة منتهية الصلاحية** — أصبحت تُعرض «للإعدام ولا تُباع» فقط، ولا يمتد عرض بعد تاريخ الصلاحية.
4. **خصم 30% ثابت على ألبان هامشها 10–15%** — أصبح يختار أكبر خصم يظل فوق التكلفة.
5. **قائمة الاقتراحات تمتلئ بنوع واحد** وتختفي البضاعة الراكدة — أصبحت متنوعة، والكميات التافهة لا تُقترح، والخاسرة تتأخر في الترتيب.
6. **تكرار نفس العرض الفاشل كل شهر** (نفس الصنف اعتُمد له عرض فاشل 5 مرات) — أصبح هناك فترة تهدئة 60 يومًا بعد عرض بلا نتيجة.
7. **نسخة الأمان قبل الاستعادة كانت في مجلد مخفي** — أصبحت في مجلد النسخ ليمكن التراجع من الشاشة.
8. **مفتاح ترخيص من مفتاح بائع قديم كان يظهر كـ«تلاعب»** — أصبح يطلب التفعيل فقط.
9. **أدوات الإصدار لم تكن داخل المستودع** بسبب قاعدة `.gitignore` واسعة — اكتشفه CI وتم إصلاحه.
10. **اختبارات كانت تعتمد على بعضها** (ملف ترخيص مشترك في مجلد المستخدم) وعلى وقت اليوم — تم عزلها.

## 8. المخاطر الحقيقية المتبقية
1. **التشغيل على Windows لم يُختبر على جهاز حقيقي**: الواجهة، الطباعة على طابعة حرارية فعلية، قارئ الباركود USB، الخطوط العربية في الإيصال، والأداء على جهاز ضعيف.
2. **المُثبّت غير موقّع**: تحذير SmartScreen سيقلق بعض العملاء؛ الحل شهادة Code Signing.
3. **نقطة البيع لا تمنع بيع دفعة منتهية الصلاحية** إذا لم تُسجَّل كتالف؛ يعتمد على تنبيه «منتهي الصلاحية» في الرئيسية وعلى الإعدام اليومي.
4. **فاعلية العروض الذكية غير مُثبتة على بيانات حقيقية**: المحاكاة أثبتت صحة الحساب والتطبيق والقياس، لا استجابة العملاء.
5. **حماية الفترة التجريبية تعتمد على سر داخل البرنامج**: تمنع العبث العادي (تعديل الملفات، إرجاع الساعة، إعادة التثبيت) لكنها لا تصمد أمام هندسة عكسية محترفة — وهذا طبيعي لبرنامج يعمل بدون إنترنت.
6. **الطلب الضائع 5.8%** في المحاكاة سببه سياسة الطلب في المحاكي (مالك افتراضي)، وهو تذكير بأن تقرير «اقتراحات إعادة الطلب» يجب أن يُستخدم.

## 9. المطلوب منك للوصول إلى «Production Ready»
1. على جهازك: `npm run license:keygen` ← احفظ المفتاح الخاص في مكانين offline ← commit لملف `public-key.ts` فقط.
2. على جهاز Windows 10/11 حقيقي: نفّذ قائمة الاختبار اليدوي في [RELEASE.md](RELEASE.md) (تثبيت، بيع، طباعة حرارية، نسخة على فلاشة، ترقية، إزالة، استعادة على جهاز آخر).
3. `git tag v1.0.0 && git push origin v1.0.0` ← يُنشأ الـRelease تلقائيًا مع `SHA256SUMS.txt`.
4. (اختياري) شهادة توقيع كود تُضاف كـ GitHub Secrets.
